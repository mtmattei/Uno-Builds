# Implementation Plan

Six vertical slices, each delivering an end-to-end demonstrable piece of the experience. Each slice is roughly half a day to a day of focused work. Build them in order — each depends on what came before. The goal of every slice is *demonstrability*: at the end of slice N, you should be able to interact with the partial app and feel real progress, not just see scaffolding.

## Slice 1 — Project skeleton, theme, and foundation panel

Set up the Uno Platform WebAssembly project with the full theming pipeline and build the static foundation panel (no chat yet).

**Scope.** Create the project from `dotnet new unoapp -tfm net10.0` with the `--preset blank` template plus `--features Material Skia SkiaRenderer Toolkit MVUX Hosting Localization`. Verify it builds and runs in WASM. Set up the resource dictionary structure: `Themes/Colors.xaml` (full palette), `Themes/Typography.xaml` (Fraunces + Martian Mono via embedded fonts), `Themes/Icons.xaml` (six platform geometries), `Themes/ChipStyles.xaml` (platform chip style with morph storyboard, runtime chip style). Implement `MainPage.xaml` with the responsive two-column grid skeleton (use `ResponsiveView` with three templates). In the right column build the foundation panel: app name `TextBox` with the bottom-border-only treatment, platform `WrapPanel` with six `ToggleButton` chips, runtime `StackPanel` with two chips, Begin button hidden until `FoundationReady` returns true. Hardcode the state in code-behind for now (no MVUX yet) — the goal is to nail the visual treatment and chip morph.

**Definition of done.** App builds and runs in Chrome and Firefox without errors. The foundation panel renders identically to the prototype: platform chips morph between text and icon visual states with the 360ms `EaseOutExpo` animation; the runtime chips toggle between `.NET 10` (with REC badge) and `.NET 9` with the correct visual treatment; the Begin button surfaces only when the foundation is ready and uses the proper solid-ink styling. Typography matches the spec — Fraunces is loaded and visible for the SerifBody styles, Martian Mono is loaded and visible for the eyebrows. No hardcoded hex values exist outside `Themes/Colors.xaml`. All visible text uses `x:Uid` localization. Reduced-motion test: setting `prefers-reduced-motion` in browser dev tools disables the chip morph storyboard.

## Slice 2 — MVUX model and chat shell

Replace the hardcoded foundation state with a real `ComposerModel` and add the chat transcript area with empty/begin states wired up.

**Scope.** Create `Models/ComposerState.cs`, `Models/ChatTurn.cs`, `Models/Artifact.cs`, `Models/LayerSuggestion.cs` records. Create `ComposerModel.cs` partial record with `IState<ComposerState>` and the foundation commands (`SetAppName`, `TogglePlatform`, `SetRuntime`, `BeginConversation`). Wire the model into DI in `App.xaml.cs`. Bind the foundation panel to model state — no more code-behind state mutation. Build `Views/ChatTranscript.xaml` as an `ItemsRepeater` over `Messages`. Create the `MessageBlock.xaml` UserControl with the entrance animation storyboard; for this slice it just renders speaker eyebrow + body text (no suggestion panel yet). Implement the empty-state caption that swaps based on `FoundationReady`. Wire `BeginConversation` to push a hardcoded "description" prompt as the first composer turn. Add the input box at the bottom of the chat column with the ResourceDictionary-driven styling.

**Definition of done.** Foundation state lives entirely in MVUX — no `private string _appName` fields anywhere. The chat shows the empty-state caption when the foundation is empty, the ready-to-begin caption when foundation is ready and messages are empty, and the description prompt as the first turn after Begin is clicked. The message entrance animation runs on first appearance of the description turn. Typing in the input box updates `InputValue` via two-way binding. Pressing Enter on a non-empty input triggers `SubmitInput` (which is still a no-op stub that just clears the input). The whole interaction is keyboard-navigable: Tab traverses foundation fields → chat input → Begin button. All foundation transitions still respect the foundation re-draft of README/CLAUDE/scaffold artifacts (even though the artifacts panel doesn't exist yet — the state changes are testable via debug overlay).

## Slice 3 — Live build artifact panel

Build the right column's artifact panel with all eight cards, the dot→check status glyph animation, and the LayerToArtifacts expansion sync.

**Scope.** Create `Views/LivebuildPanel.xaml` rendered below the foundation panel in the right column at desktop viewport, and stacked below the chat at narrower viewports. Use an `ItemsRepeater` over the `Artifacts` dictionary with a custom comparer to maintain declaration order. Build `ArtifactCard.xaml` as a `UserControl` containing the header row (`StatusGlyph` + filename + chevron + state label) and the collapsible body. Implement `StatusGlyph.xaml` as a `UserControl` with two visual states (`Planned`, `Drafted`) that animate the circle fill (320ms `EaseOutCubic`) and the inscribed checkmark stroke draw (380ms `EaseOutExpo` with 140ms delay). Implement the body's expand/collapse animation via the measure-then-pin pattern: 0 → measured height over 320ms `EaseOutCubic` with simultaneous opacity fade. Add the `LayerToArtifacts` static class. Update `ComposerModel.PushPrompt` and `ApplyAction` to set `ExpandedIds` based on the layer being pushed.

**Definition of done.** All eight artifact cards render in the right column. Foundation cards (README, CLAUDE, scaffold.sh) start drafted and animate to `Drafted` state on first render — the dot→check animation runs. The other five cards start `Planned` and remain so until applicable layers run. Clicking the Begin button transitions `ExpandedIds` to `[readme, claude]` — those two cards expand showing their drafted content with the `MonoCaption` typography in the `paper3` body. The chevron rotates 180° on expansion. Clicking a drafted card's body switches to inline edit mode with `Ctrl+Enter` to commit and `Esc` to cancel. The card height animation is smooth at 60fps in Chrome's performance profiler. Planned + expanded cards render the italic placeholder body ("Awaits your decision in the chat.") with the dashed hairline border.

## Slice 4 — Layer prompts, suggestion panel, and apply flow

Wire up the full conversational flow: each layer's prompt content, the Suggestion Panel UI, the Apply / Pick Alternative paths, and the compact-turn collapse for older composer turns.

**Scope.** Create `Models/Templates/ArtifactTemplates.cs` with pure static functions for every artifact's content (Readme, Claude, Mcp, Design, Interactions, Architecture, Plan, Scaffold). Create `Models/Templates/LayerPrompts.cs` with the `Build(string layer, ComposerState state)` function returning a `ChatTurn` for each of the six layers. Implement the description handler in `SubmitInput` (locally, no API). Implement `ApplySuggestion`, `PickAlternative`, `ApplyWithAssets` commands in the model. Build `SuggestionPanel.xaml` as a `UserControl` with the tinted card frame, the SUGGESTED eyebrow, the SerifSuggestion label, the SerifBody italic reasoning with vertical-rule, the Apply button, and the Show Alternatives toggle that expands a panel with alternative buttons (and asset inputs for the design layer). Build `CompactComposerTurn.xaml` as a `UserControl` with the StatusGlyph + layer label + applied-label + Edit pill. Add a `DataTemplateSelector` on the `ItemsRepeater` that picks `MessageBlock` (full) for the latest composer turn and `CompactComposerTurn` (collapsed) for all earlier composer turns; user turns always use `MessageBlock`. Implement the collapse swap animation (180ms opacity fade out, swap, 180ms fade in).

**Definition of done.** Walking the entire conversation works: type description → Submit → wiring prompt appears with full Suggestion Panel and Apply button → click Apply → wiring turn collapses to compact summary, mcp.json drafts (animated check mark on row), design prompt appears next with design.md auto-expanding showing placeholder body. Same pattern through interactions, architecture, plan, done. The compact turn collapse animation runs cleanly. Picking an alternative via the Show Alternatives expander correctly applies its specific updates. The design layer's asset inputs accept Figma URL, Prototype URL, Screenshot — clicking "Apply with these assets" generates DESIGN.md content that references the provided URLs. Clicking the Edit pill on a compact turn rolls back the conversation correctly: the turn becomes the new latest, downstream artifacts reset to Planned, and the chat continues from that point. Foundation re-drafts (README, CLAUDE, scaffold) trigger correctly when foundation fields change mid-conversation.

## Slice 5 — Anthropic API integration

Add the contextual reasoning fetch on description submission, plus the free-text override path for layers other than description.

**Scope.** Create `Services/IAnthropicClient.cs` Refit interface and concrete client. Wire it into DI. Create the proxy server (small ASP.NET Core minimal API project in `proxy/`) that holds the Anthropic API key and forwards `/v1/messages` requests — deploy this alongside the WASM static host. Update `IAnthropicClient` to point at the proxy URL via configuration. Implement `FetchContextualReasoningsAsync` in `ComposerModel` — fires after description submission, returns 5 sentences of layer-specific reasoning, swaps into `ContextualReasonings` state, the Suggestion Panel reads from there with a fallback to the static reasoning. Implement `SubmitFreeTextOverrideAsync` — when the developer types free text on any layer other than description, send the layer's static prompt + the user's override text + the current state to the API, expect back a JSON object with `updates` (artifact ID → content) and apply it. Add the thinking indicator UI control with the staggered three-dot animation. Add the error banner with auto-dismiss. Implement timeout escalation copy ("Hmm, let me think harder…", "Still working on it.", abort).

**Definition of done.** Submitting a description produces a fully drafted README, CLAUDE, and contextual reasoning on each subsequent suggestion that references the developer's app domain (verify by submitting "a habit tracker for runners" and seeing reasoning mention "stride data" or similar specific terms). Typing free text on any non-description layer (e.g., overriding wiring with "I want both Uno docs and GitHub MCP servers") triggers the thinking indicator, eventually returns custom artifacts, and continues to the next layer. Network failures (kill the proxy) show the error banner with the appropriate message and the chat does not advance. Rate limit (HTTP 429) shows "Rate limited. Wait a moment and try again." The API key never appears in the WASM bundle — verify by inspecting the published static files.

## Slice 6 — Bundle export, accessibility audit, polish

Implement bundle download and complete the accessibility and motion-reduction work.

**Scope.** Implement `Services/IBundleExporter.cs` and `BundleExporter.cs`. The bundle is a single Markdown file with all eight artifacts concatenated, each in its own section preceded by a `## filename.ext` header, with the artifact's content in a language-tagged code fence (`json`, `bash`, `markdown`). Use `Windows.Storage.Pickers.FileSavePicker` to trigger the WASM download. Add the Download button to the final composer turn (when `CurrentLayer == "done"`) and any other obvious download entry points. Run a complete accessibility audit: every interactive element has `AutomationProperties.Name`; focus traversal works correctly through all panels in reading order; the keyboard works the entire conversation flow without ever needing the mouse. Verify the focus ring style (`FocusVisualKind="Reveal"`) draws the 2px ink ring on every focusable element with the correct 2px offset. Implement the reduced-motion override — when `UISettings.AnimationsEnabled == false`, all storyboards skip to their final state (replace `Storyboard.BeginTime` with `0` and durations with `0:0:0.001`). Test with NVDA on Windows and VoiceOver on macOS through one full conversation cycle.

**Definition of done.** A complete conversation produces a downloadable `.md` bundle with all eight artifacts, properly fenced, that opens cleanly in any Markdown viewer or IDE. The bundle's filename is the slugified app name. Keyboard-only navigation can complete an entire conversation including foundation entry, description, all five subsequent layers, and bundle download — no mouse required at any point. Screen reader narration announces speaker labels, message content, and state changes (artifact drafted) without interruption or duplication. NVDA reads the platform chip's selected state as "Web, pressed" and unselected as "Web". VoiceOver announces the status glyph state changes. Reduced-motion preference disables every storyboard while preserving final state values — chips snap between text and icon, status glyphs swap dot for check immediately, message entrance is instant. The published bundle size (release build, brotli compressed) is under 4MB initial download.

## Notes on sequencing

The slices are sequenced so that each one ends with a working, demoable state. After slice 2 you have a foundation panel + chat shell that's already useful for a stakeholder demo of the visual aesthetic. After slice 3 the artifact panel is alive and the dot→check animation is the most distinctive thing about the app, even though no real conversation happens yet. After slice 4 the entire conversation works locally without API. After slice 5 you have the production-ready system minus polish. Slice 6 closes the gaps.

If you need to ship an MVP early, slices 1-4 plus a stripped-down slice 6 (bundle export only, skip the accessibility deep work) is a viable v0.1 — the contextual reasoning and free-text overrides from slice 5 are nice-to-haves but the core flow works without them via the static fallback reasoning.
